# v0.1.1 engineering evidence patch

This patch makes release verification self-contained in the tagged source,
corrects historical capacity resource statistics, and publishes auditable
benchmark evidence. It introduces no database migrations or API behavior changes.

- The strict client verifier pins signer commit, source commit, tagged workflow
  identity and GitHub-hosted runners. Signer digest means workflow commit SHA.
- Future releases use GitHub immutable releases. Drafts remain editable for
  validation; publication locks release assets and their tag. Existing v0.1.0
  tags/assets are preserved and remain under the original no-replacement policy.
- Resource aggregation uses standard odd/even medians with regression tests.
- Benchmark evidence includes sanitized numeric inputs, derived summaries,
  metadata and internal checksums; the release archive also has SHA-256 and
  GitHub build provenance.
- The evidence records **historical v0.1.0 candidate measurements**, not a
  v0.1.1 saturation or soak test. Short local runs are not a production SLA.
- All six binary archives plus the benchmark archive must pass checksum and
  provenance verification before the Draft can be published.
- Upgrade: no new migrations. Keep the existing reviewed configuration and
  migration checksums; follow the stop/backup/migrate/smoke procedure.
